# 实例配置（`config.json` v2）

> 本文是**配置键的完整参考**。所有示例值都是占位（`10001`、`~/...`、`https://example.invalid`），
> 真实值填在你自己的实例配置里；**不要**把真实 QQ 号/群号/token 提交到任何仓库。

## 一、配置分几层

| 层 | 载体 | 放什么 | 谁改 |
|---|---|---|---|
| ① bundle 引导配置 | profile patch 里 `dsh-onebot-qq` 的 `config:` | `dataDir` / `configPath` / `autoConnect` / `compatServer` / `compatPort` | 安装时写一次，很少动 |
| ② **实例配置** | `<dataDir>/config.json` | 本文的全部业务键 | 手改 / 控制台热改 |
| ③ 环境变量 | `QQ_IMAGEGEN_*` | 生图凭据（覆盖 ② 的 `credentials.gptImage`） | 启动 DSH 前 export |
| ④ 数据目录 | `<dataDir>/…` | 人设、表情库、群记忆、日志、会话状态等运行数据 | 机器人自己写 |

**位置**：

```
<dataDir> 优先级：bundle 配置 dataDir > 环境变量 DSH_QQ_DATA_DIR > $DSH_HOME/dsh-onebot-qq
<config>  = bundle 配置 configPath；留空 = <dataDir>/config.json
$DSH_HOME = 环境变量；留空 = ~/.dsh
```

> **改名兼容**：本插件原名 `dsh-qq-bot`。升级到 0.1.0 后，若新默认目录 `$DSH_HOME/dsh-onebot-qq`
> 不存在、而旧目录 `$DSH_HOME/dsh-qq-bot` 存在，会**自动继续使用旧目录**（配置、人设、表情库都不动）。
> 想换成新名字：把整个目录搬过去，或在 bundle 配置里显式写 `dataDir`。

> 自定义数据目录有两种正确做法（**只跑 `bin init --data-dir X` 不够**：init 只在 X 下写 config，
> 插件默认仍读 `$DSH_HOME/dsh-onebot-qq`）：
> 1. 启动 DSH 前设 `DSH_QQ_DATA_DIR=X`（推荐，最省事）；
> 2. 或改 profile 的 `cordis.patch.yml` 里 `dsh-onebot-qq` 行 `config.dataDir: '...'`
>    （profile patch 行的 `config` 是**整体替换**，要把 `dataDir/configPath/autoConnect/compatServer/compatPort` 写全）。

典型路径：Linux/macOS `~/.dsh/dsh-onebot-qq/config.json`；Windows `%USERPROFILE%\.dsh\dsh-onebot-qq\config.json`。

**要不要整个换位置**：可以。`dataDir` 写绝对路径即可；`configPath` 单独指到别处也支持。
相对路径（含人设/表情库等目录）**一律相对 `dataDir`** 解析，所以整个数据目录可以整体搬走。

### 控制台页面 ↔ 配置归属

| 控制台页 | 里面是什么（配置路径不变，只是归属/分组调整） |
|---|---|
| 群聊 | 核心项（主人 QQ / 群聊上文条数）+ `gate-wake.enabled` + `commands.enabled` + 每群卡片 |
| 唤醒 | `gate-wake` 全部可见项（门禁与唤醒、唤醒词、必须被叫、接续窗口、关键词冷却、答应声、被戳回一句）+ `anti-repeat`（防刷屏） |
| 句池 | `persona-voice` 全部可见项（句池开关、人设目录、当前人设、引用纪律） |
| 生图 | `imagegen` 全部可见项，**含生图凭据** `credentials.gptImage.*`（存储路径不变，旧配置零迁移） |
| 文件与图片 | `file-transfer` 行为类开关（总开关 / 下载时机 / 大小上限 / 数量上限 / 保留天数）+ `video-read` / `video-link-read`（看视频与视频链接，可选） |
| 其他 | 权限 / 门禁 / 文件 / 发图 / 头像 五组低频配置（原隐藏页统一并到这里，含入站目录、发图白名单、头像缓存）+ `private-friend-gate`（私聊只回好友，可选） |
| 群记忆 | `group-memory`（固定页里的「工具配置」面板） |

> 子插件页是 **27 个子插件**（19 个默认开 + 8 个默认关）的启停汇总，和各自功能页里的 `enabled` 开关**同源**（改哪边都一样）。
> 默认关的 8 个是：`backfill` / `group-repeat` / `growth` / `link-parser` / `memory` / `owner-commands` / `relationship` / `startup-recall`（要用得手动开）；「看视频 / 看视频链接」默认开但需要本地侧车，缺侧车自动降级。

## 二、最小可用配置

```json
{
  "version": 2,
  "adminQq": 10001,
  "napcat": {
    "wsUrl": "ws://127.0.0.1:3001",
    "wsToken": "YOUR_WS_TOKEN",
    "httpUrl": "http://127.0.0.1:3000",
    "httpToken": "YOUR_HTTP_TOKEN"
  }
}
```

除上面的必填项外，其余键不写就用默认值。完整默认值可用 `node bin/dsh-onebot-qq.mjs init` 生成一份。

> **不用先手改 JSON**：缺 `adminQq` 时插件进入「待配置模式」（控制台可用、工具已注册、不连 NapCat），
> 打开 设置 → QQ 控制台 →「新手向导」填主人 QQ 与 NapCat 地址即可，保存后自动连接。
> 上面的 JSON 是手改方式（改完需重启 dsh-web）。

## 三、路径规则

- 键名以 **`dir` / `file` / `path` 结尾**的字符串 → 相对 `dataDir` 解析；
- 键名以 **`whitelist` / `roots` / `dirs` / `paths` 结尾**的字符串数组 → 逐项解析；
- 以 `~` 开头 → 相对用户主目录展开；
- 已是绝对路径（POSIX `/…`；Windows `C:\…` / `C:/…` / `\\server\share` / `file://`）→ 原样使用；
- `http(s)://` URL 不当路径处理（如 `link-parser.parserUrl`）。

> 自己加配置项时照这个命名法，路径就会被自动解析，不用改代码。

## 四、核心键

### `version` / `adminQq`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `version` | int | `2` | 配置格式版本；当前只有 v2 |
| `adminQq` | int | `0` | **必填**。主人 QQ 号（唯一）。`0`/缺失 → 启动时报错；出口脱敏只有对主人私聊豁免 |

### `napcat`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `wsUrl` | str | `ws://127.0.0.1:3001` | OneBot v11 **正向 WebSocket** 地址（收消息） |
| `wsToken` | str | `""` | WS 鉴权 token（NapCat 配了才填） |
| `httpUrl` | str | `http://127.0.0.1:3000` | OneBot **HTTP API** 地址（发消息/取文件/查群） |
| `httpToken` | str | `""` | HTTP 鉴权 token |

### `dsh`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `agentPreset` | str | `""` | **全局 / 私聊线**的 agent preset 名。默认留空 = 沿用 DSH 默认（全工具），主人私聊才能读文件、跑命令；群聊线不看这个键（见下一行）。填不存在的名字 → 回退 DSH 默认工具面 |
| `groupAgentPreset` | str | `"qq-chat"` | **群聊线**用的 preset。内置 `qq-chat` 随包声明（纯聊天 + 联网，裁掉 shell / 文件 / 任务 / 技能 / 插件管理类工具）；内置 preset 可用、且配置里从没写过这个键时，启动会**自动补上并落盘**。显式写空串 = 群聊线也沿用全局 |
| `privateAgentPreset` | str | `""` | **私聊线**用的 preset；空 = 沿用 `agentPreset`（保持全工具）。只在想让私聊也走纯聊天/别的 preset 时才填 |
| `qqWorkspacePath` | path | `"workspace"` | QQ 线的会话工作目录（`AGENTS.md` / `CLAUDE.local.md` / 人设投递文件在这里）；插件启动时把这个目录注册成 DSH 工作区 |
| `workspaceTitle` | str | `"QQ 聊天"` | QQ 工作区在 DSH 侧栏的显示名。启动/保存配置时按路径创建（或复用），同路径只复用不重复创建 |
| `sessionsFile` | path | `"state/sessions.json"` | chatKey → DSH sessionId 映射（重启后能续聊） |

> 这三个 preset 键**控制台没有编辑页**（旧文档写的「DSH 连接」页并不存在）—— 要改就直接改 `config.json`，改完热重载/重启后对**新建**会话生效，已有会话保持原来的 preset。
>
> 选线顺序（`kernel/dsh-driver.js`）：`group:*` → `groupAgentPreset`，空则 `agentPreset`；`private:*` → `privateAgentPreset`，空则 `agentPreset`；仍为空 = DSH 默认。

### `outbound`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `replyMaxLength` | int | `3000` | 单条回复最大长度（超出截断/分段） |
| `longForwardThreshold` | int | `400` | 超过多少字改用「合并转发卡片」；带 @/引用的长文不套卡片 |
| `longForwardChunkSize` | int | `800` | 卡片里每段节点的长度 |
| `quoteAfterMsgs` | int | `3` | 回复发出前同群插了几条才自动挂引用；`0` = 关掉自动引用 |
| `groupContextCount` | int | `10` | 每轮给模型补多少条群聊上文（增量，旧配置 `bridge.groupContextCount` 自动迁移）；`0` = 不补 |
| `nodeName` | str | `""` | 合并转发卡片里显示的发送者名。留空 = 用 NapCat 登录昵称（`selfNickname`），再没有就写「机器人」；最长截到 24 字 |

### `archive`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 是否把进出消息写成 JSONL 留档 |
| `dir` | path | `"logs/qq_chat"` | 留档目录（每个会话一个 `<kind>_<id>.jsonl`） |

|---|---|---|---|

### `pacing`（回复节奏）

`pacing.merge.*`：同一会话多条消息的合批。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 是否合批 |
| `windowMs` | int | `2000` | 首条消息后的合批窗口 |
| `maxWaitMs` | int | `6000` | 最长等待 |
| `skipIfSlowMs` | int | `30000` | 模型慢于该值时跳过后续合批 |
| `windowActiveMs` | int | `4000` | 正在回复时的合批窗口 |
| `activeGapMs` | int | `15000` | 判定「正在聊」的间隔 |

`pacing.reply.*`：主动接话（没人叫也可能自然插话）。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `false` | 总开关 |
| `hourlyMax` | int | `6` | 每小时最多主动接话次数 |
| `minGapMs` | int | `480000` | 两次主动接话最小间隔（毫秒） |
| `silenceEnabled` | bool | `true` | 冷场找话；`false` = 只在群里有新消息时才可能接话（不再定时找话） |
| `coldSilenceMs` | int | `180000` | 群冷场多久后允许接话（仅 `silenceEnabled=true` 时生效） |
| `topicWindowMs` | int | `600000` | 话题统计窗口 |
| `topicMinMsgs` | int | `3` | 窗口内至少几条消息才算有话题 |
| `sensitivity` | float | `0.45` | 接话倾向（0–1，越大越爱接） |
| `maxChars` | int | `140` | 主动接话字数上限 |
| `groups` | array | `[]` | 允许主动接话的群号；`[]` = 不主动接话 |
| `style.splitEnabled` | bool | `true` | 是否拆条 |
| `style.splitProbability` | float | `0.5` | 拆条概率（0–1） |
| `style.splitMinLen` | int | `12` | 短于该长度不拆 |
| `style.splitDelayMs` | int | `1000` | 拆条间隔（毫秒） |
| `style.stickerEnabled` | bool | `true` | 主动接话时是否可能带表情包 |
| `style.stickerProbability` | float | `0.8` | 带表情包概率（0–1） |
| `weights.*` | float | 见下 | 接话打分特征权重，一般不用动 |

`pacing.reply.weights` 默认值：
`intercept -1.2005`、`mentionBot 1.5852`、`atOther -1.1157`、`hasQuestion 0.4807`、
`placeholderOnly -1.0281`、`selfRatio 2.6525`、`recentCount -0.0367`、
`logSecondsSinceBot 0.0571`、`pendingCount 0.1012`。

> 一般只改 `enabled` / `groups` / `hourlyMax` / `sensitivity`；权重是调参细节。
>
> **拆条/表情概率的权威值在 `pacing.reply.style`**：内核每次配置重载会把
> `persona-voice.splitReply*` 与 `stickers.offerPercent` 同步成这里的值（控制台「主动接话」页改这里）。

### `credentials`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `gptImage.protocol` | enum | `"openai-images"` | 生图协议：`openai-images`（`/images/generations` + `/images/edits`）或 `openai-chat`（`/chat/completions`，部分中转站/模型用对话接口出图） |
| `gptImage.baseUrl` | str | `""` | 生图 API 基址（OpenAI 兼容），如 `https://example.invalid/v1` |
| `gptImage.apiKey` | str | `""` | **不要写进仓库**；建议用环境变量 `QQ_IMAGEGEN_API_KEY` |
| `gptImage.model` | str | `"gpt-image-2"` | 生图模型名（以你的中转/服务为准） |

环境变量优先级（**覆盖**实例配置/控制台输入框，`loadConfig` 时就生效）：

| 环境变量 | 覆盖字段 |
|---|---|
| `QQ_IMAGEGEN_PROTOCOL` | `credentials.gptImage.protocol` |
| `QQ_IMAGEGEN_BASE_URL` | `credentials.gptImage.baseUrl` |
| `QQ_IMAGEGEN_API_KEY` | `credentials.gptImage.apiKey` |
| `QQ_IMAGEGEN_MODEL` | `credentials.gptImage.model` |

> 协议选哪个：**默认先试 `openai-images`**；如果中转站/模型只支持对话接口出图（返回 chat 响应），再切
> `openai-chat`。控制台「运维」页有「检查生图配置」按钮可验证地址/Key/模型是否可用。

### `vision`（识图：图片 → 文字）

这条 QQ 线的会话模型**不收图片输入**，所以内核先用一个 OpenAI 兼容的视觉接口把图转成一段中文描述，
再当文本塞进本轮提示词。它是两件事的底座：

- 群友发图时，她能"看见"图里有什么（否则只会如实说图片收不到）；
- 表情包自动打标（`stickers.tagging`）—— 没配 `vision` 就只收图、不打标。

配置在 `config.json` 顶层 `vision`，**全部可选**：

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 总开关。但 `baseUrl` 或 `apiKey` 缺任意一个也等于关（日志会 warn「没配对 → 识图关闭」）；`false` = 强制关 |
| `baseUrl` | str | `""` | 视觉接口基址（OpenAI 兼容，写到 `/v1` 为止，**别带** `/chat/completions`），如 `https://example.invalid/v1` |
| `apiKey` | str | `""` | 视觉服务 key。**不要写进仓库** |
| `model` | str | `"glm-4v-flash"` | 视觉模型名 |
| `maxTokens` | int | `600` | 输出上限（夹在 1–1024） |
| `timeoutMs` | int | `30000` | 单张超时（毫秒，最小 3000） |
| `maxBytes` | int | `8388608` | 图片超过这个字节数就不上传（最小 64KB），省流量也避免 400 |
| `cacheLimit` | int | `200` | 内存里按「图片内容哈希 + 提问」缓存多少条描述（表情包会反复出现，命中率很高）；重启即空 |

> 行为：一条消息最多看 **4 张**图；全部读不出来时原样降级（把图照旧丢给模型，由它如实说没看见，不瞎猜）。
> 识图失败只写日志、绝不影响聊天；成功时描述以「[图的内容（自动识图，不是用户说的话）]」前缀进提示词。

### `compat`（可选兼容网关）

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `imageRoots` | array | `[]` | `:3971` 兼容网关可发的图片白名单根目录（`compatServer: true` 时才有意义） |

是否启动兼容网关由 bundle 配置 `compatServer` / `compatPort` 控制（默认关、端口 3971）。

## 五、子插件配置（`pluginConfig.<id>.*`）

每个子插件的键来自它的 `configSchema`；不写 = 用默认值。控制台「QQ 控制台」按 `group` 分页渲染。
**路径类默认值都相对 `dataDir`**，例如 `personaDir: "personas"` = `<dataDir>/personas`。
标「默认关」的插件（`enabled` 默认 `false`）需要手动打开：控制台对应页 / 「子插件」页的开关，或 `pluginConfig.<id>.enabled: true`。
下面按管线顺序（`order`）排列。

### `owner-commands`（order 3，群聊总开关）

一句话静音所有群：主人私聊发 `/stop-groups`（或 `#命令-关闭群聊功能`）→ 写标记文件，之后**所有群消息在拦截阶段就被掐掉，一条都不进模型**（零 token）；同时**出站也关闸**：任何发往 `group:` 的消息（模型回复、复读 +1、自主唤醒主动搭话、表情包）都会被拦下。`/start-groups`（或 `#命令-开启群聊功能`）→ 删标记恢复。**默认关**。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `false` | 插件总开关。关着时**完全不干活**：群消息照常进模型；两个斜杠命令仍出现在 `/help` 里，但调用不生效（不执行、不回执，当普通聊天往下走） |
| `stateFile` | path | `"state/owner-commands-groups-off.flag"` | 关闭标记文件：**存在 = 群功能关闭**，删掉 = 恢复。重启后天然生效（不另存内存状态）；换路径就换标记位置 |

> 只在**私聊**生效：群里发这几个写法一律当普通聊天。非主人发既不执行也不报错。留档在更早的阶段已经写完，这里只掐「进模型」。
>
> 出站闸门是 2026-11-04 补的：在这之前只掐「进模型」，复读 +1（跑在 `passive-tap`，比拦截更早）和自主唤醒（直接投 prompt）两条路都不经过那道门，群里照样冒话。

### `stranger-shield`（order 5，防攻略）

主人以外的任何人（群里或私聊）试图用话术把她"拐"过去时，在**软层**加一道约束：每轮注入「这是外人，不是主人」的硬约束，并识别套话/操控话术。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 开：非主人回合注入硬约束 + 检测话术；关：软层全停。**代码级工具门不受这个开关影响**（关了外人照样碰不到电脑/记忆） |
| `injectHint` | bool | `true` | 每轮给外人回合注入那段硬约束（只进提示词，**不会发给对方**）；关 = 只检测不提示（不推荐） |
| `detectManipulation` | bool | `true` | 识别五类话术（让她当主人 / 套主人信息 / 情感操控 / 指令注入 / 记忆投毒）：命中只追加一句提醒 + 记一行日志，**不拉黑、不回绝**（避免误伤正常聊天） |

### `gate-wake`（order 10，门禁与唤醒）

### `backfill`（order 62，补回复）

每 `intervalMin` 分钟看一眼**主人私聊**的历史，找出「她最后一条真回复之后」主人发的消息，挑最近的塞回会话让她补一句。已经补过的 messageId 记在状态文件里，同一批永远不会补第二遍。**默认关**。

|---|---|---|---|

| `firstDelaySec` | int(秒) | `60` | 启动后首次检查延迟（刚起来时 NapCat 往往还没连上） |
| `maxPerRun` | int | `5` | 一次最多补几条；改大 = 会把话题拉回更早的时候 |
| `historyCount` | int | `30` | 每次从最近多少条私聊里找漏消息 |
| `seedFirstRun` | bool | `true` | 开：首次运行只把现有历史记为已处理（避免装插件瞬间补一堆旧消息）；关：第一次就跑补回复 |

> 和 `context-gap`（断档补上下文）分工：本插件是**后台定时**主动补；`context-gap` 是主人回来那一轮把漏消息当上下文带上。
> 另：连续失败 3 次会停 30 分钟再试，避免模型侧挂了一直重复烧钱。

### `context-gap`（order 63，断档补上下文）

| `historyCount` | int | `30` | 每次拉多少条私聊历史（只在断档后的那一轮拉一次） |

> 只查**主人私聊**（群聊/别人的线不写盘）；没有漏的就什么都不推，只多一次 NapCat 查询，不污染提示词。

| `qqFavorite` | bool | `true` | 收到新表情时顺便存进这个 QQ 账号的「收藏表情」（腾讯侧），发出去就是真表情样式、手机 QQ 里也能看到；关 = 只存本地。需要协议端支持 `add_custom_face`（SnowLuma 有，原版 NapCat 没有） |
| `maxPerTurn` | int | `1` | 每轮最多发几张 |

### `growth`（order 85，成长日记）

每天到点写一篇当天日记到 `<dataDir>/state/growth/YYYY-MM-DD.md`，并把最近两天的日记（硬截断）拼进提示 —— 她回话时"记得"自己写过什么。**默认关**。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `false` | 插件总开关（关 = 不写也不注入） |
| `hour` / `minute` | int | `23` / `0` | 每天几点写日记；错过会在启动时补写 |
| `minChars` | int | `200` | 日记最少字数（只是提示词里的目标，写短了不重写） |
| `maxChars` | int | `400` | 日记最多字数；超过**硬截断** |
| `materialChars` | int | `1500` | 喂给模型的当天聊天素材上限（字）；越大越贵 |
| `timeoutSec` | int(秒) | `120` | 生成超时；超时按失败处理，走本地兜底 |
| `catchUp` | bool | `true` | 启动时补写错过的日记（一天最多试一次，失败当天不重试） |
| `injectEnabled` | bool | `true` | 把最近两天日记拼进提示；关 = 照写但不进对话 |
| `injectChars` | int | `300` | 注入上限（字，硬截断）。每轮都要带上，别调太大 |
| `injectScope` | enum | `"masterPrivate"` | 注入范围：`masterPrivate` 只主人私聊 / `master` 主人（私聊 + 群）/ `all` 所有会话 |

> 日记由一次性后台会话生成（`runIsolatedTask`），落盘由插件自己做；那个会话里 `mcp__qq__*` 工具一律被拒，日记不会被误发到聊天里。

### `memory`（order 85，事实记忆）

给"事实"单独一层：每轮把本会话最相关的几条事实带进上下文，并给模型 `remember(text, importance)` / `memory_recall(query)` 两个工具。**默认关**。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `false` | 插件总开关（关 = 不注入，工具也拒绝写入；已存的文件不动） |
| `dir` | path | `"state/memory"` | 记忆目录，事实写在 `items.json`。和群记忆的 `qq-memory` **完全分开**，互不覆盖 |
| `injectEnabled` | bool | `true` | 每轮回话前自动注入事实；关 = 只剩工具按需检索（更省 token） |
| `prefixEnabled` | bool | `true` | 最稳定的一批事实放进「会话级静态前缀」（每个会话只注入一次、之后吃 KV 缓存）；关 = 退回每轮都拼进提示（每轮全价重发）。需要内核支持 `registerPrefixProvider` |
| `injectMaxChars` | int(字) | `800` | 注入字数预算，超了按整条/整字截断。硬上限就是 800，调大无效 |
| `injectMaxItems` | int(条) | `10` | 每轮最多注入几条（按相关度优先，其次重要度/新鲜度），上限 18 |
| `pruneEnabled` | bool | `false` | 定时归档（软删除：标 `archived`，仍能检索、只是降权）。默认关；改了要重启/重载插件才生效 |
| `pruneIntervalHours` | int(小时) | `24` | 归档间隔（只在上面打开时生效） |
| `archiveThreshold` | float | `0.2` | 归档分数阈值：`0.7×重要度 + 0.2×新鲜度 + 0.1×使用频率`（0–1），越低越不轻易归档 |
| `archiveAfterDays` | int(天) | `90` | 多少天没出现才允许归档；重要度 5 的核心事实永不归档 |

> 记忆写入只给**主人回合**：群里/非主人私聊调 `remember` 会被代码级工具门拒掉（防记忆投毒）。

### `relationship`（order 86，关系状态）

维护「她和他」的亲密度 `confidence`（30–95），并在主人回合注入一句关系状态。**默认关**。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `false` | 插件总开关（关 = 不读不写也不注入） |
| `decayHour` | int(小时) | `4` | 每天几点朝 50 衰减（一天结束后没人聊天的时候） |
| `decayStep` | int | `2` | 每次衰减往中间走几点（95 大约 23 天回到中性） |
| `ignoreAfterMin` | float(分钟) | `30` | 她主动开口后超过这么久他还没说话 → `confidence -1`；支持小数（排障时可设 `0.02`） |
| `coldEnabled` | bool | `true` | 记录被冷落（减 1）；关 = 关系只涨不跌 |
| `dailyPlusCap` | int(点) | `5` | 每天最多涨多少（按自然日算，跨天重置）；**减分不受这个限制** |
| `injectEnabled` | bool | `true` | 每轮告诉她「你和他现在的关系：confidence=… 心情=…」（只给主人看） |
| `injectChars` | int | `120` | 注入上限（硬截断）。每轮固定开销，别调太大 |
| `maxNotes` | int | `20` | `notes` 备注保留条数（只影响文件，不参与判断） |

> 状态存 `<dataDir>/state/relationship.json`；每次加减/衰减后原子写。主动接话轮（没人叫她）不算互动。

### `air-reading`（order 90，读空气）

用**规则**补 `pacing.reply` 那 9 个权重算不出来的几种情况（不调模型、零成本）：超长公告、连续对聊、深夜、没文字内容。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 开：补几条「这时候别接话」的规则；关：完全交给 `pacing.reply` 的权重模型 |
| `maxChars` | int(字) | `150` | 超过这个字数的消息当成公告/长文，不接（50–1000） |
| `quietHours` | str | `"2-6"` | 深夜时段，形如 `2-6`（支持跨零点 `22-6`）；留空 = 不启用 |
| `quietPenalty` | int(%) | `60` | 深夜时段有百分之几的概率直接不接（不归零） |
| `monologueWindow` | int | `3` | 最近这么多条都是同一人/同一对人、且没有她 → 不插嘴（2–10） |

> 只拦「没人叫她」的插话：**私聊 / @ / 引用 / 唤醒词 / 接续窗口 / 入群欢迎一律放行**，不干扰别的插件判定。

### `group-memory`（order 90，群记忆）

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 插件总开关（关 = 不注入记忆指针、`read_memory` 报错；不影响积累） |
| `dir` | path | `"qq-memory"` | 记忆目录（每群一篇 `<群号>.md`） |
| `maxBytes` | int | `24000` | 单篇读取上限（字节，按整行截断）。**控制台保存也按它限制**；超过的部分模型读不到。合并写回以**未截断原文**为基准，超限只影响进上下文的文本，不会再把尾部写丢。 |
| `accumulateEnabled` | bool | `true` | **自动积累**总开关（插件自带定时器，不依赖外部 cron） |
| `accumulateIntervalHours` | int | `8` | 更新频率：积累间隔（小时） |
| `accumulateMode` | enum | `"digest"` | `digest` 增量要点（一轮一次调用，**模型用 `memory_append` 工具按群提交要点**，默认）/ `rewrite` 重写全文 / `per-group` 逐群（仅排障） |
| `accumulateBatchMaxChars` | int | `200000` | 单次提示词上限（字）；群太多超过它就自动拆成多次调用 |
| `accumulateLookbackHours` | int | `72` | 首次/水位之前最多回看多少小时的聊天 |
| `accumulateKeepDays` | int | `3` | **原始记录保留天数**（车轮清理；0 = 永不删） |
| `accumulateKeepRows` | int | `0` | 每群最多保留多少行原始记录（额外上限；0 = 不限） |
| `accumulateMsgPerGroup` | int | `200` | 每轮每群最多取多少条消息（**超出部分按采样跳过**，结果里的 `sampledOut` / 日志会写明，不回补；要更高覆盖率就调大它或缩短间隔） |
| `accumulateMaxChars` | int | `8000` | 每群喂给模型的正文上限（字符） |
| `accumulateMinNewMsgs` | int | `20` | 少于多少条新消息就跳过该群（省 token；0 = 有消息就积累） |
| `accumulateSectionMaxItems` | int | `80` | 记忆文件每节条目上限（超出从最早丢） |
| `accumulateRetainRevisions` | int | `20` | `.revisions/` 保留多少份历史版本（0 = 不备份）。控制台手改留下的 `-manual` 备份也按这个数清理。 |
| `accumulateMaxGroupsPerRound` | int | `12` | 单轮最多处理多少个群；其余下轮**轮转**处理（不会让大号段群永远轮不到） |

> 积累流程：定时器到期（或控制台点「立刻积累一轮」）→ 每群取「上次消化之后」的聊天留档
> → **一轮把所有有新消息的群合成一次模型调用**（默认 `digest`：模型逐群调用 `memory_append`
> 工具提交新增要点，本地按 QQ/事实去重、把「这轮…」临时内容丢掉后合并；`rewrite`：模型重写全文再整篇替换）→ 原子写回 `<dir>/<群号>.md`，
> 旧版备份到 `.revisions/`（积累器与控制台 save 共用一套命名与保留策略）→ **车轮清理**：删掉「已消化 且 早于 `accumulateKeepDays` 天」的原始记录
> （未消化的不删，避免丢历史）。
>
> **水位口径**：每群只取最近 `accumulateMsgPerGroup` 条 / `accumulateMaxChars` 字，水位记录的是**本轮实际喂到的最新一条消息 ts**（不是写完时刻），
> 所以模型调用期间新到的消息不会被标成已消化；更早被采样跳过的条数计入 `sampledOut`（控制台/日志可见，不回补）。
> 模型跑在独立的一次性后台会话：**只放行 `memory_append`**（提交要点）；`send_message` / 生图 / `bash`
> 等其它工具一律禁用（不占 QQ 线、不会往群里发消息）；工具没提交的群走正文兼容解析，仍漏就记失败、下轮重试。
> 控制台「群记忆」页显示：每 N 小时 / 积累方式 / 原始记录保留 / 上次结果 / 下次预计时间；开关与参数在「工具配置」里改。

## 六、控制台（新手向导与热改）

### 新手向导的三个入口

| 入口 | 位置 | 用途 |
|---|---|---|
| **新手向导清单** | 总览页顶部 | 逐项 ✅/❌：配置文件 / 主人 QQ / NapCat 连接 / 人设 / 生图（可选），每项一句「怎么做」；未完成时顶部有醒目提示条；小字显示 `版本 · 数据目录 · 配置路径` |
| **NapCat 连接** | 「NapCat 连接」页 | 图文步骤 + `wsUrl` / `httpUrl` / token 输入；**「测试 NapCat 连接」/「重新连接 NapCat」按钮在「运维」页**（先保存再测） |
| **生图配置** | 「生图」页 | 协议（`openai-images` / `openai-chat`）、API 地址、模型（带建议）、API Key（掩码）；**「检查生图配置」按钮在「运维」页** |

> 人设不用手动创建：插件首次启动会**自动投递内置默认人设「蓝色大肥鱼」**；换/加人设的写法见
> [使用说明书 §6](使用说明书.md#6-人设怎么写) 的「人设怎么写」。

> 首次启动缺 `adminQq` 时插件处于「待配置模式」（见 §七）：控制台可用、工具已注册、**不连 NapCat**；
> 填完保存后**自动连接**，不需要重启 dsh-web。

### 热改说明

- 入口：DSH Web → 设置 →「QQ 控制台」。
- 写配置流程：**备份** `config.json.bak-console-<时间戳>` → **原子写** → `kernel.reloadConfig()`；
  失败自动回滚旧文件。
- 生效范围：改完**立即生效**（插件每轮现读 `bot.cfg`）；不需要重启 dsh-web。
- 有些键不是「终端配置」：如 `plugins.<id>=false`（硬卸载）属于启动期装配，改后需重启。
- 手改 `config.json` 也行：保存后重启 dsh-web 生效（控制台热改不用重启）。
- Windows 记事本可能给文件加 UTF-8 BOM —— 内核读配置会剥 BOM；但保存后建议确认 JSON 合法。

## 七、校验与失败行为

- 启动时校验**必填项**：`adminQq` / `napcat.wsUrl` / `napcat.httpUrl`，以及
  `dsh.sessionsFile` / `dsh.qqWorkspacePath` / `archive.dir` 必须是字符串路径；
  `credentials.gptImage.protocol` 只允许 `openai-images` / `openai-chat`。
- **只有 `adminQq` 缺失时 = 「待配置模式」**：**不报错退出**，`kernel.configReady=false`；
  控制台可用、工具已注册、**不连接 NapCat**；日志 warn
  「实例配置未完成（缺 adminQq）…控制台可继续配置」。
- 其它必填项缺失/非法（NapCat 地址、路径、protocol）：仍抛中文错误（含配置文件路径），修好重启。
- 控制台保存成功（或 `kernel.reloadConfig()` / 应用运行时配置成功）后：`configReady=true`；
  若此前是待配置模式且 bundle 配置 `autoConnect` 未关 → **自动连接 NapCat**（失败只 warn 不抛）。
- 配置文件不存在：自动创建一份默认配置（`adminQq: 0`）→ 进入待配置模式（不是直接报错）。
- 旧格式（含 `bridge` 段的 v1 配置）：读取时自动迁移（仅内存）；要落盘请用 `node bin/dsh-onebot-qq.mjs import-legacy <旧配置>`（见 [排错](排错.md) §七）。
